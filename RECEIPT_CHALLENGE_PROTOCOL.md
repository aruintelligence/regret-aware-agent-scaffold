# Frozen extension: preinference receipt claims

**Freeze point:** This protocol, code and CI workflow must be committed before the next real-model calls. The [original prospective cohort protocol](PROSPECTIVE_LEDGER_PROTOCOL.md) and its archived hash remain immutable. This extension adds receipt claims to the same pinned public QA cohort, model, grade rubric, groups and research watch target. No result is required to be favorable.

1. The `prepare` CI step, before model initialization, creates 120 nonce-bearing HMAC request receipts for the 120 frozen issue rows using an ephemeral key distinct from ingress and monitoring keys. Its plan binds the exact receipt count and ordered SHA-256 digest. This single CI runner retains the claims; **no customer receives a receipt**.
2. Before any inference, `run` verifies the complete frozen plan and each receipt against the current closed ingress checkpoint. It rejects missing, changed, duplicate or unbound receipts. The original prospective protocol's real-model calls, one-to-one grade reconciliation and signed watch then proceed unchanged.
3. Afterward, `verify` checks all receipts again, replays the complete issued/graded/model evidence, and writes the receipt count/digest and an explicit `independent_customer_receipt_delivery=false` into the accounting report. Archive the receipt claims and this protocol hash with the existing evidence bundle, without raw questions, passages, answers or secret keys.

**Predeclared success criterion:** `issued=receipts=observed=graded=120`; every receipt challenge is included in the closed manifest, exact report recomputes, and `automatic_rollout_permitted=false`. Report error count, execution failures, source certificates and alarm irrespective of their values. Unit tests require changed receipts to block inference and fail later verification. No accuracy outcome or absence of alarm is a success criterion for the receipt control.

**Interpretation:** This exercises receipt creation and verification before and after real calls under one CI authority. It does not prove timely customer delivery, independent receipt issuance or ingress operation, external timestamping, durable key retention, the truth of grades, or requests that never received a receipt. Archived HMACs cannot be reauthenticated after ephemeral keys are gone. A customer pilot requires separate issuers and keys, actual held receipts, current externally retained checkpoints, atomic unique request IDs and independent grade review. See the [challenge design and limits](CLIENT_RECEIPT_CHALLENGE.md).
