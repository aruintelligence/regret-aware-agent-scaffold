# Frozen preinference request-accounting audit

**Freeze point:** This protocol, code and CI workflow are committed before the new model calls on reserved questions. Do not alter the selection, model, rubric, accounting rules or target after seeing outcomes. If the audit fails, preserve the failure. This tests the research implementation, not a customer assurance service.

## Reserved cohort and method

- Dataset: official public Stanford SQuAD v1.1 development JSON, SHA-256 `95aa6a52d5d6a735563366753ca50492a658031da74f301ac5238b03966972c9`. SHA-256 sort of question IDs, reserved offsets **680–799**, 120 answerable requests. Earlier studies used offsets 200–679. Question IDs are disjoint; articles may overlap.
- Model: `distilbert/distilbert-base-cased-distilled-squad` revision `564e9b582944a57a3e586bbb98fd6f0a4118db7f`, CPU inference, source-offset proof verification. The research grader counts a result correct only if it is accepted with verified source grounding and has normalized token F1 at least 0.5 against published human answers. Exceptions and abstentions count as errors.
- Groups, fixed before calls: original context length at most 600 characters (`short_source`) versus longer (`long_source`); monitor both and aggregate. Fixed ordered groups `["short_source","long_source"]`.
- Watch: current fixed six-bet anytime e-process, prospective target error **0.5**, familywise α **0.05**, over groups and aggregate. This high research target is not a product service level. No alarm is not evidence of safety.

## Ordering and completeness

1. In its **own CI step before model initialization**, `aru-watch-prospective-audit prepare` verifies the dataset checksum and writes an ordered manifest of 120 planned requests. Each opaque `request_id` is SHA-256 of the dataset checksum, official question ID, source context and question; there is no raw question, passage or answer in the manifest. The step signs a closed-cohort checkpoint with an ephemeral ingress HMAC key and fixes model revision, rubric, groups, target, alpha and betting grid. The job records the protocol checksum. A separate step receives the checkpoint fingerprint.
2. Only after that checkpoint exists, `aru-watch-prospective-audit run` validates the entire frozen plan **before** model initialization, performs 120 real calls, scores against published human answers, and converts the observed ordered results to grades. The complete-outcome reconciler signs the watch using a distinct ephemeral monitoring HMAC key only if every preissued request has exactly one grade. A failed call remains an explicit error. Missing, duplicate, reordered, mismatched or extra outcomes must not produce a signed alarm-free report.
3. A third step, `aru-watch-prospective-audit verify`, recomputes the manifest from the pinned dataset, checks the checkpoint signature and supplied fingerprint, reconciles all grades and independently recomputes the real-model watch from the ordered outcome trace. It compares all counts, alarms, scope and hashes. The workflow archives the protocol hash, manifest, checkpoint, grades, signed watch and aggregate reports. No raw prompts, passages or answers or HMAC keys are uploaded.

**Predeclared success criterion:** the prepared manifest has 120 requests before inference; all 120 actual calls are represented; `issued=graded=observed=120`; the exact report and both watches recompute; zero silent exclusions; report `automatic_rollout_permitted=false`. Report the observed error count, model-call failures, verified source certificates and any alarm, even if unfavorable. Unit tests require changed/stale preparation to block inference and altered or missing grades to fail verification. No specific accuracy or alarm outcome is required to pass the accounting test.

## Interpretation

This CI job uses **one runner and one repository grading implementation**. It orders preparation before inference, but it does not establish a separately operated ingress service, independently authenticated grader, durable public timestamp, secret retention or a hidden test set. Its HMAC keys are ephemeral and deliberately excluded from artifacts, so later readers can verify SHA-256 evidence and rerun public inference but **cannot reauthenticate the old HMACs**. The public SQuAD development split and shared articles also leave the watch's conditional-null assumptions unproven. A prospective customer pilot would need separate operators and keys, durable external checkpoints, auditable model-call receipts, independent grade review, and an agreed representative error target. No production rollout follows from this audit.
