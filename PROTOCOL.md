# Decision-bound experiment protocol

The opt-in protocol fixes the baseline and candidate routing policies, grading rubric identifier, bootstrap settings, and advisory review thresholds in a canonical JSON object. `lock-protocol` writes it without overwriting an existing file. The canonical SHA-256 digest is inserted into every subsequent decision, including decisions supplied by the vendor-neutral `external_adapter.log_instrumented_decision(..., protocol_path=...)`.

Evaluate with `--protocol` to check that **every** decision has that digest, every available outcome uses the planned rubric, and the policy pair and analysis settings match. A mismatch stops evaluation before a report is written. Logs without a protocol remain available for exploratory analysis; the advisory human-review screen does not pass them. The HTML report names the binding status and digest. An optional evidence manifest can also include the protocol file using `attest --protocol ...` and `verify --protocol ...`.

The digest is a consistency check, not proof of prospective registration. An operator who controls both the data and local protocol can rewrite both after seeing outcomes. To establish *when* a plan existed, archive or publish its digest with an independent trusted timestamp **before** collecting any decisions or labels. Authentication of an evidence bundle with an HMAC requires a separately protected key; neither the HMAC nor the protocol validates the truth of external labels.

A useful pilot should predefine task inclusion criteria, a stable rubric, blind independent grading, the route choice mechanism, a data retention policy, and how missing or delayed labels will be handled. The code cannot enforce those real-world conditions. The time-uniform result in [ANYTIME_EVIDENCE.md](ANYTIME_EVIDENCE.md) addresses optional stopping for a fixed policy pair on logged contexts under conditional randomization; it does not establish a future-population benefit or correct a plan created after seeing results.
